# Ограничения

Чего проверки не доказывают и где могут ошибиться, с причинами. Как устроены проверки:
[CHECKS.md](CHECKS.md).

## internet

1. **TUN и прокси-клиент распознаются только по TTL 255.** Локальным считается только ответ ICMP
   с TTL 255. TUN, который не отвечает на ping или отвечает с другим TTL, не распознаётся, и
   TCP-соединение через него засчитывается как доступ к удалённому узлу. Наоборот, устройство в
   том же сегменте, ответившее за публичный адрес с TTL 255, считается локальным.
   Причина: в TCP приложению не виден TTL, единственный признак локального ответа даёт ICMP.
2. **Системный прокси Windows не используется.** HTTP-проба берёт прокси только из переменных
   окружения `HTTP_PROXY` и `NO_PROXY` (адрес пробы обычный HTTP). Там, где интернет доступен
   только через прокси из настроек Windows, проба не проходит и вердикт будет `offline`,
   `dns_broken` или `limited` в зависимости от того, какие прямые пробы проходят.
   Причина: `http.ProxyFromEnvironment` из стандартной библиотеки Go.
3. **Только IPv4 для адаптеров, ICMP и TCP.** В сети только с IPv6 подключение может показать
   лишь HTTP-проба. Причина: список адаптеров запрашивается для `AF_INET`, цели ICMP и TCP
   заданы адресами IPv4.
4. **Зависимость от серверов NCSI Microsoft.** Если `www.msftconnecttest.com` заблокирован или
   недоступен, вердикт будет `limited`, `captive` или, при блокировке имени через DNS,
   `dns_broken` при рабочем интернете. Причина: только точный ответ этого сервера даёт `online`,
   а DNS-проба разрешает то же имя.
5. **`net.dns.ok` может прийти из кэша.** Имя разрешается системным резолвером, который отвечает
   из кэша. Ответ из кэша может скрыть неработающий DNS-сервер: если узел достижим, а HTTP-проба
   не проходит, вердикт будет `limited` вместо `dns_broken`; если HTTP-проба тоже получает адрес
   из кэша и проходит, вердикт будет `online`. Без достижимого узла вердикт в любом случае
   `offline`. Причина: проверка не обращается к DNS-серверу напрямую.

## inventory

1. **`productState` разбирается эвристикой.** Формат поля WMI `productState` Microsoft не
   документирует, разбор по битам 12-15 и 4-7 взят из общепринятой практики. При другом формате
   состояние может быть неверным или `unknown`. Причина: документированный WSC API не всегда
   доступен, WMI остаётся запасным источником.
2. **Без Центра безопасности уровни определяются по компонентам Windows.** Если WSC не ответил
   по любой причине, списки берутся из WMI. Если не ответил и WMI (`inv.wsc.unavailable` и
   `inv.wmi.unavailable`), уровень АВ определяется только по Defender, сторонний АВ не
   учитывается, и если Defender не защищает, вердикт `inv.verdict.unknown`. Сторонний МЭ тоже не
   виден, уровень МЭ определяется по брандмауэру Windows, и если он не фильтрует, вердикт тоже
   `inv.verdict.unknown`. Так ожидаемо будет на Windows Server, где нет Центра безопасности.
3. **Центр безопасности показывает то, что продукты сообщают о себе.** Продукт может сообщать
   `on` при неработающем ядре или хранить устаревшее состояние: Defender остаётся в списке после
   остановки своей службы (как `snoozed`). Записи Defender при остановленной `WinDefend`
   не учитываются, для остальных продуктов такой поправки нет. Причина: другого источника
   состояния сторонних продуктов нет, поэтому работу проверяют `firewall` и `antivirus`.
4. **Defender оценивается по четырём признакам.** Учитываются служба, защита в реальном времени,
   признак включённого антивируса и режим работы. Исключения, облачная защита и защита от
   изменений не читаются. Если состояние службы `WinDefend` не удалось запросить или WMI Defender
   не отвечает при работающей службе, о защите ничего не утверждается
   (`inv.defender.unavailable`).
5. **Следы продуктов ищутся по фиксированной таблице.** Продукты вне таблицы из 19 записей не
   находятся, папка может остаться после удаления продукта. Следы на вердикт не влияют.
6. **МЭ, не зарегистрированный в Центре безопасности, не виден.** Вердикт учитывает только
   брандмауэр Windows и сторонние МЭ из Центра безопасности.

## firewall

1. **Проверка правилом проверяет только брандмауэр Windows.** У стороннего МЭ свои правила. Если
   брандмауэр Windows не фильтрует, а сторонний МЭ включён, проверка правилом пропускается
   (`fw.rule.third_party`), и доказать работу может только проверка политики. Если включены оба,
   проверяется только брандмауэр Windows.
2. **Групповая политика.** При `NET_FW_MODIFY_STATE_GP_OVERRIDE` локальные правила не
   применяются, и проверка пропускается (`fw.rule.gp_override`). Если это значение прочитать не
   удалось, проверка идёт, и проигнорированное правило будет выглядеть как `not_enforced`.
3. **Только исходящий TCP.** Правило и проверка политики касаются исходящих TCP-соединений.
   Входящая фильтрация, UDP и ICMP не проверяются, действие по умолчанию для входящих только
   читается.
4. **Доказывается применение нового правила, а не качество политики.** Проверка правилом
   показывает, что брандмауэр применяет правило к программе. Правила пользователя не
   оцениваются, проверка политики касается только введённых адресов.
5. **Совпадение со сбоем сети.** Любая ошибка соединения при действующем правиле считается
   блоком. Восстановление после удаления правила отсекает обрыв сети, но сбой, начавшийся сразу
   после добавления правила и закончившийся до повторного соединения, будет принят за блок.
6. **Классификация проверки политики.** Доказательством считаются только `WSAEACCES` и тайм-аут
   при работающей сети. МЭ, который отвечает отказом или сбросом, даст `inconclusive`.
   Блокировка по DNS тоже даёт `inconclusive`. Тихий сброс у провайдера или мёртвый узел при
   включённом МЭ засчитываются как блок. Соединения идут напрямую, без прокси. Причина: отказ и
   сброс может прислать любой узел по пути, а тихий сброс выглядит одинаково, где бы он ни
   произошёл.
7. **Нужен хотя бы один контрольный узел.** Проверке правилом и классификации тайм-аутов нужен
   доступ к одному из `1.1.1.1:443`, `8.8.8.8:443`, `77.88.8.8:443`. Если все недоступны, итог
   `fw.rule.control_failed` и `inconclusive`.
8. **Правило может остаться после аварийного завершения.** Отмена проверки или её тайм-аут
   3 минуты только прекращают ожидание в окне: повышенная копия не завершается принудительно и
   сама удаляет своё правило. Если копия падает или её завершают извне, отложенное удаление не
   выполняется. Тогда правило остаётся до следующей проверки правилом, которая удаляет его
   первым шагом. Оно касается только `mamori.exe` и одного адреса.
9. **Вызовы COM проверки правилом без тайм-аута.** Зависший вызов `INetFwPolicy2` держит
   копию, которая его сделала. Через повышенную копию окно при отмене перестаёт ждать; в
   повышенном процессе и в `--probe` проверка ждёт вызов.
10. **Loopback не проверяется.** Все цели публичные. Фильтрует ли брандмауэр Windows трафик
    `127.0.0.1` и `::1`, программа не проверяет и ничего об этом не утверждает.

## antivirus

1. **EICAR зависит от проверки при доступе и времени ожидания.** АВ без защиты файлов в
   реальном времени, с исключением для `%TEMP%` или `.txt`, или проверяющий файлы только при
   запуске, даст `av.eicar.not_detected`. То же, если АВ реагирует дольше ожидания (15 с по
   умолчанию, настраивается).
2. **`ERROR_ACCESS_DENIED` неоднозначен.** Код 5 засчитывается как блок антивирусом, потому что
   так отвечают некоторые АВ, но он возможен и по другим причинам: права на папку, другая
   программа защиты. Любое изменение содержимого файла тоже засчитывается как реакция.
3. **AMSI зависит от зарегистрированного провайдера.** `AmsiScanString` передаёт строку
   провайдеру AMSI. Сторонний АВ без провайдера AMSI даст `av.amsi.not_detected` или
   `av.amsi.unavailable` при рабочей защите, вердикт будет `partial`. Результаты `AMSI_RESULT_BLOCKED_BY_ADMIN` (16384-20479)
   считаются необнаружением. Без `amsi.dll` или её экспортов AMSI недоступен.
4. **Только тестовые образцы.** EICAR знает любой антивирус, тестовую строку AMSI распознаёт
   провайдер AMSI, если он зарегистрирован (пункт 3). Обнаружение образцов
   показывает, что цепочка проверки работает, но ничего не говорит о качестве обнаружения
   настоящих угроз.
5. **Уведомления и журналы.** АВ показывает уведомление об угрозе, записывает событие в журнал
   и карантин; в управляемой среде обнаружение может уйти в консоль службы безопасности.
   Причина: для АВ это обычное обнаружение. Об уведомлении предупреждает страница завершения
   установщика.
6. **Файл может остаться.** Если АВ держит папку дольше четырёх попыток удаления, остаётся папка
   `%TEMP%\mamori-av-*` (находка `av.eicar.cleanup_failed` с путём).
7. **Длинное ожидание прерывается тайм-аутом.** В окне на одну проверку отведено 3 минуты, в
   `--probe` 5 минут на весь запуск. Ожидание EICAR больше этого завершит проверку с
   `common.cancelled`.

## Реализация и CI

1. **Зависший вызов COM или WMI в `secprod` занимает горутину.** Это касается чтения Центра
   безопасности, состояния брандмауэра Windows и Defender, в `inventory` и на шаге состояния
   `firewall`. Ожидание прекращается через 15 с, но горутина, а под `withCOM` из `secprod` и
   закреплённый поток ОС, остаются до возврата вызова. Библиотека `wmi` выполняет запросы по
   одному под общей блокировкой, поэтому зависший запрос задерживает следующие запросы WMI, и
   каждый из них прекращает ожидание через 15 с. У вызовов COM проверки правилом тайм-аута нет,
   см. `firewall`, пункт 9.
2. **На раннерах GitHub выключен Defender.** Раннеры Windows работают на Windows Server без
   Центра безопасности, защита Defender в реальном времени там выключена. Поэтому модульные
   тесты в CI идут с `-short`, а `e2e` проверяет структуру результатов, уборку правил и блок при
   фильтрующем брандмауэре, но не может показать работу АВ: проверка `antivirus` там ожидаемо не
   проходит.
3. **Живые тесты не меняют систему.** `go test` без `-short` читает Центр безопасности, службы
   и настройки брандмауэра, открывает сетевые соединения и сканирует строку AMSI в памяти, но не
   добавляет правил и не пишет EICAR. Последовательность проверки правилом проверяется на поддельном брандмауэре,
   реакция АВ на EICAR в автоматических тестах не воспроизводится.
